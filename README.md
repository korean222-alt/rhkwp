# LectureLens

강의 탭의 화면과 소리를 내 PC에서 한국어·영어 자막, 장면 노트, ZIP으로 정리하는 웹 앱입니다. React + TypeScript + Vite로 만들었으며 GitHub 저장소를 Vercel에 연결해 사용할 수 있습니다.

**현재 범위는 웹 베타입니다.** 최대 4개 강의 탭의 독립 화면/오디오 캡처, 실제 로컬 음성 인식, 모바일 파일 사용 안내, 비저장 이미지→TXT, 파일 대기열, 무음 자동 종료, 이어 처리, 내보내기를 구현했습니다. 사용자 요청대로 결제는 나중에 연결합니다. 로그인, 결제, 클라우드 동기화, Windows exe/MCP는 포함하지 않습니다. 실제 1시간 강의 검증과 배포 후 확인은 아래 체크리스트에 남겨 두었습니다.

## 터미널 없이 GitHub → Vercel

1. 제공된 `lecturelens-source.zip`을 풉니다.
2. GitHub에서 새 저장소를 만듭니다. `Add file → Upload files`에서 **lecturelens 폴더 안의 내용**을 올립니다. ZIP 파일 자체를 올리는 것이 아닙니다. 저장소 첫 화면에 `package.json`, `pnpm-lock.yaml`, `vercel.json`, `src`, `public`, `scripts`가 보여야 합니다. 숨김 파일 `.gitignore`와 `.github`도 포함해 주세요. 파일 개수 제한이 나타나면 폴더별로 나눠 올리거나 GitHub Desktop으로 올릴 수 있습니다.
3. Vercel에서 `Add New → Project`를 눌러 그 저장소를 가져옵니다.
4. Framework Preset은 **Vite**, Root Directory는 저장소 루트, Output Directory는 **dist**입니다. `lecturelens` 폴더째 저장소에 올렸다면 Root Directory를 `lecturelens`로 지정합니다.
5. `Deploy`를 누릅니다. 설치와 빌드 명령은 `vercel.json`에 고정한 pnpm 버전으로 실행됩니다. 별도의 API 키, 데이터베이스, 환경 변수는 필요하지 않습니다. Node.js는 `package.json`의 24.x를 사용합니다.
6. 나온 HTTPS 주소를 **PC Chrome/Edge**에서 열고 예시 강의, 짧은 실제 강의, ZIP 다운로드를 확인합니다. Preview와 Production 주소는 브라우저 저장 공간이 서로 다릅니다. 강의를 계속 보관할 때는 같은 Production 주소를 사용하세요.

Vercel 설정 근거: [설치 명령과 패키지 관리자](https://vercel.com/docs/package-managers), [Node.js 버전](https://vercel.com/docs/functions/runtimes/node-js/node-js-versions). 실제 Vercel 계정 배포는 아직 수행하지 않았습니다.

## 다른 작업을 하면서 녹화하기

1. 별도 탭에서 강의를 엽니다.
2. LectureLens에서 `화면 녹화 시작`을 누릅니다.
3. 공유 창의 **Chrome 탭 → 강의 탭 → 탭 오디오 공유**를 선택합니다. 전체 화면을 공유하면 다른 작업의 화면도 저장되므로 강의 탭을 선택하세요.
4. 소리 레벨을 확인하고 `작은 상태 창`을 엽니다. 이 창에는 녹화 시간, 소리, 일시 정지, 장면 저장, 종료 버튼이 있습니다.
5. 다른 탭이나 다른 프로그램에서 작업합니다. 최신 PC Chrome/Edge에서는 별도 영상 작업자와 AudioWorklet이 캡처를 이어갑니다. 작은 상태 창을 닫아도 녹화는 계속됩니다.
6. `종료하고 정리하기`를 누르고 남은 자막 처리가 끝나면 ZIP을 받습니다.

앱과 강의 탭은 닫지 마세요. 컴퓨터가 절전 모드로 들어가거나 공유를 중지하면 캡처가 중단됩니다. 화면 Wake Lock은 브라우저가 허용하는 동안만 적용되므로 장시간 사용 시 OS 절전 설정을 확인하세요. F9는 앱에 포커스가 있을 때 동작합니다. 다른 프로그램에서는 작은 창의 장면 저장 버튼을 사용하세요. 해당 브라우저가 백그라운드 화면 처리를 지원하지 않으면 앱이 안내를 표시합니다.

## 언어와 글자 인식

- 강의 언어 기본값은 **한국어**입니다. 혼합 강의는 **한국어 + 영어 · 혼합 인식**을 선택하세요. 짧은 음성 구간마다 Whisper 언어 토큰의 한국어/영어 점수를 비교한 뒤 선택한 언어로 원문을 전사합니다. 영어로 번역하지 않습니다. 혼합 인식은 언어 판별 때문에 처리 시간이 더 걸리며, 한 문장에 섞인 짧은 외국어, 전문 용어, 소음은 틀릴 수 있습니다. 자막은 연필 버튼으로 수정합니다.
- 이전 버전의 자동 모드는 언어를 생략하면 영어를 기본으로 쓰는 [Transformers.js 3.8.1 동작](https://github.com/huggingface/transformers.js/blob/3.8.1/src/models.js)을 제대로 처리하지 못했습니다. 저장된 이전 설정도 한국어 기본값으로 전환합니다. 이미 확정된 자막의 원음은 삭제되어 있으므로 기존 잘못된 결과를 자동 복원할 수는 없습니다. 설정을 확인하고 원본을 다시 재생하거나 파일을 다시 가져오세요.
- 지나치게 길거나 지속적으로 반복되는 자막은 짧은 구간으로 다시 인식합니다. v1.1.1에서는 띄어쓰기 없는 `야야야…` 같은 글자 반복도 검사하고, 자막 저장 직전에도 다시 검사합니다. GPU에서 반복 오류가 계속되면 CPU로 재시도합니다. 그래도 실패하면 해당 구간의 원음을 삭제하지 않고 경고와 함께 보관합니다. 강의 언어와 모델을 바꿔 `저장된 구간 다시 처리`를 사용할 수 있습니다. 짧은 말 더듬기·웃음·두 번 반복한 문장은 유지하며 모든 오인식이나 반복을 판별하는 기능은 아닙니다.
- 이전 버전에서 이미 저장한 잘못된 자막은 자동 복원하지 않습니다. 완료한 구간의 원음은 공간을 절약하기 위해 삭제되므로, 연필 버튼으로 직접 수정하거나 원본 영상을 다시 가져와야 합니다. Whisper의 반복 생성·환각은 [공식 모델 설명](https://github.com/openai/whisper/blob/main/model-card.md#performance-and-limitations)에 명시된 한계입니다.
- tiny는 가볍고, base/small은 더 많은 자원을 사용합니다. CPU에서는 tiny로 먼저 확인하세요. WebGPU 초기화 실패 시 CPU로 전환하며, GPU 실행 중 실패한 구간은 CPU 모드로 바꿔 이어 처리할 수 있습니다.
- **자동 화면 글자 읽기는 제거했습니다.** 촬영 시 보관용 JPEG만 만들며 OCR용 PNG나 자동 판독 작업을 생성하지 않습니다. 이전 버전의 자료는 지우지 않지만 화면 글자 편집과 OCR 도구는 제공하지 않습니다.
- **이미지 → TXT**: 직접 선택·끌어넣기·Ctrl+V로 넣은 PNG/JPG/WebP/BMP를 원본 해상도로 읽습니다. 한국어와 영어를 함께 읽으며 결과를 편집·복사·TXT 다운로드할 수 있습니다. 입력 이미지와 결과는 서버 전송, IndexedDB, localStorage 저장 없이 현재 화면 메모리에서만 다룹니다. 화면을 떠나거나 지우면 해제합니다. 글자 인식 모델은 첫 사용 시 다운로드·캐시합니다. 최대 25MB, 2,400만 화소입니다.
- small 위에 **large-v3-turbo**를 추가했습니다. WebGPU의 shader-f16 지원 시 q4f16(모델 파일 합계 약 564MB), 그 외 GPU는 q4(약 759MB), CPU는 q8(약 1.1GB)을 사용합니다. 사용 RAM/GPU 메모리는 파일 크기보다 클 수 있습니다. 음성용 상위 모델이며 이미지 OCR 모델을 바꾸는 기능은 아닙니다. 출처: [공식 모델 설명](https://huggingface.co/openai/whisper-large-v3-turbo), [ONNX 가중치 목록](https://huggingface.co/onnx-community/whisper-large-v3-turbo/tree/main/onnx). 다운로드 포함 실행 결과는 QA.md에 기록했습니다.

## 사진 저장과 자막 변화

기본은 **장면 전환만**입니다. 첫 화면 1장과 안정된 장면 전환만 저장하며 10초마다 반복 촬영하지 않습니다. 하단 25%는 자막 영역으로 보고 변화 감지에서 제외합니다. 감지에서만 제외하며 실제 사진에는 화면 전체가 포함됩니다. 설정에서 제외 범위를 0~40%로 바꿀 수 있습니다.

자막 위치를 완벽하게 자동 분류하는 방식은 아닙니다. 제외 영역 밖의 자막, 강사의 움직임도 화면 변화로 감지될 수 있으며 제외 영역에만 있는 슬라이드 변화는 놓칠 수 있습니다. 이런 영상은 `자동 촬영 → 끄기 · 수동 저장만`을 선택하세요. 이 모드에서는 자동 사진을 만들지 않으며 F9 또는 작은 상태 창의 `장면 저장`을 눌렀을 때만 저장합니다. 필요하면 `장면 전환 + 일정 간격`을 직접 선택할 수 있습니다. 구형 기본 주기 촬영 설정은 장면 전환만으로 이전됩니다. v2에서 직접 고른 촬영/언어 설정은 유지합니다.

녹화 중 홈 화면의 **촬영 설정 변경**, 설정 화면, 작은 상태 창에서도 자동 촬영 모드를 바꿀 수 있습니다. 메인 화면에서는 감지 기준·제외 영역·간격·JPEG 크기/품질도 바꿀 수 있습니다. 다음 사진부터 적용되며 오디오 녹음을 끊지 않고 기존 사진도 유지합니다.

**무음 자동 종료·저장** 스위치를 켜고 1~120분을 지정할 수 있습니다. 기본은 꺼짐입니다. 자막 처리 지연을 무음으로 판단하지 않고, 5초 오디오 블록의 음성 에너지 검사로 연속 무음을 누적합니다. 종료할 때 마지막 오디오도 저장합니다. 일시 정지 시간은 제외하며 오디오 트랙이 없으면 자동 종료하지 않습니다. 음악·잡음은 소리로 잡힐 수 있고 조용한 실습은 무음으로 판단될 수 있습니다.

강의 창이 가려지거나 최소화되면 플랫폼에 따라 **검은 화면으로 캡처되거나 캡처되지 않을 수 있습니다**. 앱의 백그라운드 작업 지원과 원본 영상 플랫폼의 렌더링은 별개입니다. 원본 영상이 보이게 두고 첫 장면을 확인하세요. 화면 공유 선택 전, 녹화 중, 작은 창, 도움말에 안내를 표시합니다.

## 여러 강의

파일을 여러 개 선택하면 선택 순서대로 실제 재생 속도로 가져오고 강의별로 분리합니다. 한 파일의 자막 처리까지 마친 뒤 다음으로 넘어갑니다. 「다음 파일 처리 취소」는 현재 강의를 유지하며 대기 파일을 취소합니다. 오류가 나면 다음 파일을 자동 시작하지 않고 저장된 자료를 유지합니다. 미시작 파일은 메모리에만 있으므로 새로고침 후 다시 선택해야 합니다.

PC Chrome/Edge에서는 첫 강의를 녹화한 뒤 **다른 탭 강의 추가**로 최대 4개를 동시에 연결합니다. 공유 창에서 매번 서로 다른 **Chrome 탭 + 탭 오디오 공유**를 선택해야 합니다. 브라우저 전체나 마이크의 스피커 소리를 녹음하는 방식이 아니라 탭의 디지털 오디오를 각각 받으므로 다른 탭의 소리가 자막에 섞이지 않습니다. 같은 탭 안의 영상 여러 개는 소리가 섞이므로 영상마다 탭을 나눠야 합니다. 창/전체 화면이나 오디오 없는 소스가 있으면 동시 녹음을 추가할 수 없습니다.

강의별 이름·시계·소리 레벨·일시 정지·촬영 설정·무음 자동 종료·종료 버튼이 있습니다. 작은 상태 창의 강의 선택으로 조작 대상을 바꿀 수 있습니다. 공유를 취소하거나 잘못된 소스를 추가해도 기존 강의는 계속됩니다. 모든 강의의 녹음은 동시에 저장하지만, 큰 모델을 여러 번 메모리에 올리지 않도록 자막은 한 모델에서 강의별로 차례로 처리합니다. 인식이 재생을 따라가지 못하면 대기 음성과 디스크 사용량이 늘어납니다. 기기 성능에 맞춰 1~2개부터 확인하세요.

지원 브라우저에 `suppressLocalAudioPlayback`을 요청해 공유한 탭의 스피커 재생을 억제합니다. 지원 여부와 실제 재생 동작은 브라우저에 따라 다릅니다. 플레이어 자체의 음소거는 녹음도 무음으로 만들 수 있으므로 각 강의의 소리 레벨을 확인하세요. 실제 Chrome 두 탭의 독립 오디오 검사는 QA.md에 기록했습니다. 출처: [Chrome 화면 공유 제어](https://developer.chrome.com/docs/web-platform/screen-sharing-controls), [공유 탭의 로컬 재생 억제](https://developer.mozilla.org/en-US/docs/Web/API/MediaTrackConstraints/suppressLocalAudioPlayback).

학교·회사 페이지의 자동 다음 강의 이동에 대한 검토는 [LECTURE_AUTOMATION.md](LECTURE_AUTOMATION.md)에 기록했습니다. 사이트 자동 클릭/브라우저 확장 기능은 현재 제공하지 않습니다.

## 모바일과 모델 다운로드

모바일에서는 **이미지 → TXT**와 **기기에 녹화한 영상·음성 파일 가져오기**로 사용할 수 있습니다. Android Chrome/iOS Safari는 웹 화면 공유 API를 지원하지 않아 PC처럼 다른 탭을 직접 녹음할 수 없습니다. 앱은 미지원 브라우저에서 화면 녹화 버튼을 비활성화하고 파일 사용 방법을 안내합니다. 휴대폰의 화면 녹화에서 내부 오디오도 들어갔는지 확인한 뒤 파일을 가져오세요. 상세 방법과 제한은 [MOBILE_USE.md](MOBILE_USE.md)에 있습니다. 실제 Android/iPhone 기기 시험은 수행하지 않았습니다.

음성 모델은 **모델 미리 준비하기** 또는 첫 음성 인식에서 브라우저에 다운로드하고 캐시합니다. 별도 프로그램을 설치하지 않습니다. 모바일에서는 tiny부터 시작하고 처리 중 앱을 화면에 띄워 두세요. 잠금·다른 앱 전환으로 작업이 중단될 수 있습니다. PC와 휴대폰 자료가 자동 동기화되는 기능은 없으므로 TXT/ZIP으로 옮깁니다.

## 저장과 이어 처리

오디오는 AudioWorklet에서 16kHz 모노로 만들고 5초마다 IndexedDB에 저장합니다. 약 30초씩 음성 작업자에 보내며 완료된 오디오 PCM은 지웁니다. 전체 영상 파일은 저장하지 않습니다. 파일 가져오기는 긴 파일 전체를 메모리에 풀지 않도록 **실제 재생 속도**로 진행합니다.

저장된 강의, 이미지, 모델 캐시는 브라우저의 **디스크 공간**을 사용합니다. 컴퓨터나 브라우저를 껐다 켜도 같은 브라우저 프로필과 같은 주소에서 다시 볼 수 있습니다. 시크릿 모드, 브라우저 데이터 삭제, 브라우저의 저장 공간 정리는 보존을 보장하지 않습니다. 중요한 결과는 ZIP으로 받으세요. 처리 중에는 음성 모델, 현재 음성 구간, 현재 영상 프레임도 **RAM**을 사용합니다. 왼쪽 저장량은 RAM 사용량을 표시하는 값이 아닙니다.

새로고침/종료로 중단되면 `내 강의 → 저장된 구간 다시 처리`를 누릅니다. 저장 완료된 오디오를 처리하며 녹화 소스 자체는 다시 공유해야 합니다. 종료 직전 최대 5초는 저장되지 않았을 수 있습니다. 다른 기기, 다른 브라우저, 다른 도메인으로 자동 이동하지 않습니다. 브라우저 데이터 삭제 전에는 ZIP을 받으세요. 하나의 LectureLens 앱 안에서는 최대 4개 강의 탭을 동시에 녹화합니다. 서로 다른 LectureLens 앱 탭이 동시에 저장/처리를 소유하는 것은 Web Locks로 막습니다.

## 결과물

```text
강의이름/
  transcript.txt
  transcript.srt
  scenes.json
  frames/0000.jpg ...
  combined.md
  meta.json
```

자막의 `보시면`, `이 그래프`, `이 표` 등의 단서에 해당 장면의 이미지 경로를 붙입니다. 같은 장면은 연속해서 중복 첨부하지 않습니다. 자막의 **타임라인 켜짐/꺼짐** 버튼은 화면·TXT·복사·combined.md에서 시각 표시를 숨기거나 켜며 강의마다 저장됩니다. 전체 ZIP에도 반영됩니다. SRT와 scenes.json의 실제 시각은 유지됩니다. 시점 조회는 요청 시각 이전의 가장 가까운 화면을 기준으로 합니다. 자동 촬영을 끄면 수동으로 저장한 이미지만 포함됩니다. Chrome의 파일 저장 API에서는 ZIP을 파일로 순차 기록합니다. 미지원 브라우저에서는 180MB 이내 결과를 메모리 ZIP으로 제공합니다.

## 선택 기능: 내 API 키로 AI 분석

기본 녹화/자막/이미지→TXT/통합 노트에는 유료 AI API가 필요 없습니다. `AI 분석`에서는 본인의 Claude API 키와 모델 ID를 입력하고, 구간/전송 자료/이미지 상한/비용 추정을 확인한 뒤 실행합니다. 모델 ID와 요금은 사용자가 현재 사용 중인 모델 기준으로 입력합니다. 키는 기본 세션 한정이며 `기억하기`를 고르면 해당 브라우저 로컬 저장소에 평문으로 보관한다는 안내가 나옵니다.

이 기능을 사용할 때만 승인한 자막 및 허용한 이미지를 **Anthropic API**에 직접 보냅니다. 키도 API 인증을 위해 Anthropic에 전달됩니다. 개발자의 서버로 중계하지 않으며 개발자 키는 포함하지 않습니다. 실제 유료 API 계정 호출은 미검증이고, 요청/도구 루프는 모의 응답으로 확인했습니다. 예상 비용 상한은 입력한 단가와 보수적 토큰 추정에 따른 제어이며 청구액 보증은 아닙니다.

## 로컬 개발 및 검증

Node.js 24와 pnpm 11.25.0, Chrome이 필요합니다.

```sh
pnpm install --frozen-lockfile
pnpm dev
pnpm test
pnpm build
pnpm test:browser
```

기본 주소는 `http://127.0.0.1:5173/`입니다. build/dev에서 ONNX 및 OCR 작업자 자산을 설치 패키지에서 `public/vendor`로 준비합니다. `public/vendor`, `dist`, `node_modules`를 GitHub에 올릴 필요가 없습니다. 잠금 파일은 올려야 합니다. GitHub Actions는 테스트와 빌드를 실행합니다. Linux의 실제 백그라운드 브라우저 검증은 `xvfb-run --auto-servernum pnpm test:browser`로 실행합니다.

추가 검증 스크립트는 `scripts/`에 있습니다. 실제 음성 인식/OCR 검증은 첫 실행에 모델 다운로드가 필요하며 유료 API 키는 사용하지 않습니다.

```sh
# 별도 터미널: 배포와 같은 CSP 헤더를 적용한 dist 서버
node scripts/serve-production.mjs
# 혼합 음성 파일 가져오기부터 실제 두 언어 자막까지
node scripts/integration-check.mjs
# 실제 Chrome 두 탭의 디지털 오디오 분리 + 작은 창 제어 + 종료 저장
node scripts/native-tabs-check.mjs
# 직접 넣는 이미지의 실제 OCR + 비저장 + TXT
node scripts/ocr-check.mjs
# 상위 음성 모델 실제 GPU 실행 (큰 모델 다운로드)
node scripts/runtime-check.mjs --turbo --gpu --production
# 개발 서버에서 합성 1시간 분량의 저장/새로고침/이어 처리
node scripts/storage-check.mjs
```

## 공개 전 확인

[QA.md](QA.md)에 실제 측정값과 검증 범위를 기록했습니다. 설계서의 **실제 1시간 강의** 통과 조건을 합성 저장 시험으로 대체했다고 표시하지 않습니다.

- [ ] Production HTTPS 주소에서 실제 강의 탭과 오디오를 공유해 끝까지 자막 생성
- [ ] 한국어/혼합 강의 1시간, 시각 정합 ±2초, 실제 저장 용량 측정
- [ ] 다른 프로그램 사용/백그라운드 장시간 사용 후 자막과 장면 누락 확인
- [ ] 중간 새로고침 후 저장된 구간 이어 처리 및 ZIP 확인
- [ ] 일반 노트북에서 tiny/base/small 및 WebGPU 속도/메모리 비교
- [ ] 본인 BYOK 계정으로 작은 비용 상한을 설정해 실제 AI 요청 확인

결제 연결 시에는 서버에서 로그인, 결제 웹훅, 구독 권한을 확인하는 구조가 추가로 필요합니다. 현재 웹 앱에는 유료 이용 권한 제어가 없습니다.
